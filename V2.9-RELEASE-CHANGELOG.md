# 3. Bugs / Reliability Problems Addressed

## 3.1 Wayland environment missing when launched outside a terminal

### Old behavior / problem
Processes launched by a desktop environment, application launcher, or menu may not inherit `WAYLAND_DISPLAY`.

That can cause Quickshell or other Wayland-dependent components to start from a launcher but fail to connect to the compositor, even though the same command works from a terminal.

### New fix
The new package introduces centralized Wayland environment recovery through `lw_ensure_wayland_env()` and uses it from launcher-related scripts.

Relevant new/updated components:

- `livewallpaper/scripts/launch_quickshell.sh`
- `livewallpaper/scripts/launch_debian_wayland_safe.sh`
- `livewallpaper/scripts/open_app.sh`
- `livewallpaper/scripts/utils.sh`

### Status
**FIXED / HARDENED**

The new source explicitly documents this as a previously encountered startup problem.

---

## 3.2 Quickshell startup reliability

### Problem
A launcher-started Quickshell process could fail silently when the Wayland environment was incomplete.

### New fix
The launch path now:

1. Checks the Wayland session.
2. Recovers a valid Wayland socket when necessary.
3. Sets the required Qt Wayland platform environment.
4. Starts Quickshell through the hardened launcher path.

### Status
**FIXED / HARDENED**

---

## 3.3 Wallpaper restart sometimes failed to return

### Problem
The wallpaper process could be stopped/restarted while stale state or process ownership caused the new instance not to appear reliably.

### New fix
The new package contains explicit restart/liveness handling in the wallpaper panel and lifecycle scripts.

The source contains a documented reliability fix for the case where a restart "sometimes" did not bring the wallpaper back.

### Status
**FIXED / HARDENED**

---

## 3.4 Stale `mpvpaper` process before a new wallpaper launch

### Problem
A stale wallpaper renderer could remain attached to a monitor and interfere with the next launch.

### New fix
`start_wallpaper.sh` contains an explicit performance/reliability fix to terminate the stale `mpvpaper` instance for the target monitor before starting the replacement.

### Status
**FIXED / HARDENED**

---

## 3.5 Wallpaper switching through MPV IPC

### Problem
Rapid wallpaper navigation could race with the previous IPC operation.

The source documents a case where a second Next/Previous operation could occur before the previous transition/state update had completed.

### New fix
`PlaybackService.qml` now advances the internal navigation/current-path state through the corrected navigation target path.

`_mpv_ipc.py` also contains a documented wallpaper-switch fix involving MPV `loadfile` / filter handling.

### Status
**FIXED / HARDENED**

---

## 3.6 MPV / wallpaper process zombie-orphan handling

### Problem
Directory watching and wallpaper lifecycle processes could leave zombie/orphan processes after restart, directory changes, or session changes.

### New fix
`watch_wallpaper_dir.sh` contains explicit zombie/orphan handling and lifecycle corrections.

### Status
**FIXED / HARDENED**

---

## 3.7 Tray icon not appearing

### Problem
The previous tray implementation depended on spawning through `pystray`, which could make the tray unreliable.

### New fix
`_tray_icon.py` was rewritten to communicate with the StatusNotifierItem D-Bus interface directly.

`TrayService.qml` also contains documented fixes for tray dependencies and lifecycle behavior.

### Status
**FIXED / HARDENED**

---

## 3.8 Tray Open/Close reliability

### Status
**FIXED / HARDENED**

# 5. Smart / Automation Features Added

## Collections

The new package introduces wallpaper collections/groups with create, rename, delete, recolor, assign/remove, toggle, and random selection operations.

Data:

`livewallpaper/data/collections.json`

---

## Scheduling

Time-of-day wallpaper scheduling was added.

Rules can select:

- a collection,
- a specific wallpaper,
- sunrise,
- sunset.

The scheduler is evaluated periodically and avoids unnecessary wallpaper relaunches when the active rule has not changed.

---

## Sunrise / Sunset

Sunrise/sunset calculation is performed locally using the bundled solar-position implementation.

No cloud API is required for the solar calculation.

---

## Weather-based wallpapers

Weather rules were added using Open-Meteo.

Supported condition categories include:

- Clear day/night
- Cloudy
- Fog
- Rain
- Snow
- Storm

The implementation uses caching and periodic polling rather than constantly requesting weather data.

---

## Smart Accent Color

A dedicated `SmartAccentService.qml` and supporting bridge/script were added for dynamic accent-color functionality.

---

## AWWW transitions

The new build adds compositor-side AWWW fade transitions for image/GIF wallpaper workflows while retaining MPV/mpvpaper for video workflows.

# 14. Caveat

This report distinguishes **source-documented fixes** from **live reproduced bugs**.

A source comment saying `FIX` proves that the code was intentionally changed to address a known problem; it does not, by itself, prove that every historical failure mode was reproduced again on the current machine.

For a future release, the strongest evidence is:

1. reproduce the old failure,
2. run the new build,
3. verify the failure no longer occurs,
4. add a regression test where practical,
5. record the exact environment and result.
