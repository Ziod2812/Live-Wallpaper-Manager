# 3. Reliability / Bug Fixes and Hardening

## 3.1 Wayland environment missing when launched outside a terminal

### Problem

Applications started from a desktop launcher may not inherit the same Wayland environment available in an interactive terminal. In particular, `WAYLAND_DISPLAY` may be missing even though a Wayland compositor is running.

### v2.9 change

The v2.9 scripts introduce centralized Wayland environment recovery through `lw_ensure_wayland_env()`.

The launcher path can:

1. Detect the active Wayland session.
2. Recover the compositor socket when `WAYLAND_DISPLAY` is missing.
3. Set the appropriate Qt Wayland platform environment.
4. Continue through the hardened Quickshell launch path.

### Status

**FIXED / HARDENED**

---

## 3.2 Quickshell startup reliability

### Problem

The launcher previously depended on timing and environment state when starting Quickshell from a desktop/launcher context.

### v2.9 change

`livewallpaper/scripts/open_app.sh` contains explicit startup-race handling and Wayland recovery. The script no longer relies only on a fixed delay before interacting with the running shell.

Related launch components include:

- `livewallpaper/scripts/open_app.sh`
- `livewallpaper/scripts/launch_quickshell.sh`
- `livewallpaper/scripts/launch_debian_wayland_safe.sh`
- `livewallpaper/scripts/utils.sh`

### Status

**FIXED / HARDENED**

---

## 3.3 Wallpaper restart reliability

### Problem

Stopping and restarting a wallpaper could leave stale process state or ownership information that prevented the replacement wallpaper from appearing reliably.

### v2.9 change

`start_wallpaper.sh` contains explicit lifecycle/restart handling and uses an operation lock to reduce start/stop races.

### Status

**FIXED / HARDENED**

---

## 3.4 Stale `mpvpaper` process before a new wallpaper launch

### Problem

A stale `mpvpaper` process could remain attached to a monitor and interfere with the next wallpaper launch.

### v2.9 change

`livewallpaper/scripts/start_wallpaper.sh` explicitly checks for a stale `mpvpaper` process for the target monitor and terminates it before launching the replacement.

### Status

**FIXED / HARDENED**

---

## 3.5 MPV IPC wallpaper-switch reliability

### Problem

Rapid wallpaper switching could race between IPC operations. The previous implementation could issue a second operation before the first state transition was fully settled.

### v2.9 change

`livewallpaper/scripts/_mpv_ipc.py` contains an explicit wallpaper-switch fix around MPV `loadfile` / filter handling and bounded state polling.

`PlaybackService.qml` also contains corrected navigation/current-path handling.

### Status

**FIXED / HARDENED**

---

## 3.6 Zombie/orphan watcher processes

### Problem

Wallpaper directory watchers could survive their parent process and remain active after restart, directory changes, or session changes.

### v2.9 change

`livewallpaper/scripts/watch_wallpaper_dir.sh` contains explicit zombie/orphan handling. The watcher is started and cleaned up in a way intended to prevent detached `inotifywait` processes from being left behind.

### Status

**FIXED / HARDENED**

---

## 3.7 System tray not appearing reliably

### Problem

The previous tray implementation relied on `pystray`, which could be unavailable or incompatible with the tray host/protocol used by Wayland panels.

### v2.9 change

The tray helper uses the StatusNotifierItem D-Bus interface directly.

Relevant components:

- `livewallpaper/Services/TrayService.qml`
- `livewallpaper/scripts/_tray_icon.py`

The service also cleans up orphaned tray helper instances before starting a new one.

### Status

**FIXED / HARDENED**

---

## 3.8 System tray Open/Close lifecycle

### Problem

Tray helper lifecycle and Open/Close actions could become ambiguous when multiple Quickshell sessions or stale tray processes existed.

### v2.9 change

`TrayService.qml` manages the helper process explicitly, kills stale instances before starting, and performs cleanup when the shell exits.

### Status

**FIXED / HARDENED**

---

## 3.9 Cava visualizer horizontal positioning

### Problem

The Cava/Peaclock dock previously adjusted the content inside the visual strip rather than correctly repositioning the dock as a whole.

### v2.9 change

`CavaService.qml` adds dedicated horizontal-position handling for the Peaclock/Cava dock and stores the position in its own setting.

### Status

**FIXED**

---

## 3.10 Cava start/stop race

### Problem

Starting and stopping Cava concurrently could race between the starter and stopper processes.

### v2.9 change

`CavaService.qml` explicitly prevents the starter and stopper from running concurrently and defers operations when the conflicting process is still active.

### Status

**FIXED / HARDENED**

---

## 3.11 Visualizer clipping / layout handling

### Problem

The visualizer dock could suffer from clipping, scroll/layout issues, or malformed Cava frames.

### v2.9 change

The service contains bounded frame handling and layout/position corrections.

### Status

**FIXED / HARDENED**

---

## 3.12 Manager window IPC lifecycle

### Problem

Manager/window IPC startup and shutdown could be sensitive to shell initialization order and stale state.

### v2.9 change

The Manager launcher and IPC path were hardened together with the broader Quickshell startup sequence.

### Status

**FIXED / HARDENED**

---

## 3.13 GPU detection robustness

### Problem

GPU detection/refactoring could produce regressions when the detected driver/vendor information differed from the expected layout.

### v2.9 change

The GPU manager implementation was expanded and accompanied by dedicated regression tests.

### Status

**FIXED / HARDENED**

---

## 3.14 GPU statistics robustness

### Problem

GPU statistics/refactoring introduced compatibility cases that required explicit validation.

### v2.9 change

The v2.9 package contains a dedicated GPU statistics test suite and the corresponding service/script structure.

### Status

**FIXED / HARDENED**

---

## 3.15 File/path safety

### Problem

Wallpaper and configuration operations need to distinguish valid local paths from unsafe or ambiguous user-controlled strings.

### v2.9 change

The package adds centralized path-hardening logic, canonical-path handling, atomic file writes, and explicit validation in relevant scripts.

### Status

**HARDENED**

### Status

## 4.4 Weather backend

The v2.9 package contains a weather backend using Open-Meteo.

Backend components:

- `livewallpaper/Services/WeatherService.qml`
- `livewallpaper/scripts/weather.sh`
- `livewallpaper/scripts/weather_tick.sh`

Supported condition categories include:

- Clear day/night
- Cloudy
- Fog
- Rain
- Snow
- Storm

The implementation caches weather data and polls periodically. The default polling value in `settings.json` is 20 minutes.

### Important UI status

**The current v2.9 Manager UI does not expose a Weather Wallpapers page, location editor, or weather-rule editor.**

The backend is present in the release package, but it should **not** be described as a current user-configurable Weather UI feature.

The v2.9 `PlaylistPage.qml` explicitly documents that the former Location and Weather-based wallpaper sections were dropped rather than moved.

### Status

**BACKEND ADDED / UI CONFIGURATION NOT EXPOSED**
